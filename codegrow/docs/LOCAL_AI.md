# 浏览器本地 AI 导师

CodeGrow 的本地模式通过固定版本 `@mlc-ai/web-llm@0.2.85` 在浏览器 WebGPU 中运行 Qwen2.5-Coder；GitHub Pages 只提供网页，不承担 GPU 推理，也不需要用户填写 API 密钥。

这里的“免费”指**没有模型 API 推理费用**，不是零成本：首次下载消耗带宽和存储，生成回复占用电脑 GPU、内存和电力。模型能力、速度和正确率不等同于 ChatGPT，不承诺某款显卡的实际吞吐量；请编译运行代码核实建议。

## 使用方法与硬件

1. 在 Windows 最新版 Chrome 或 Edge 中打开 CodeGrow 的 HTTPS 网页，并启用浏览器硬件加速、更新显卡驱动。
2. 在“设置 → AI 私人导师”选择“免费本地 AI · 浏览器 GPU”，或在导师窗口使用模型启动面板。
3. 选择模型和下载来源，点击“下载并启动本地 AI”。打开页面、选择模式或切换课程都不会自动下载模型权重。
4. 等待下载、GPU 初始化完成和“本地 AI 已就绪”，再发送问题。回复会逐步显示；可以停止生成、取消加载或释放显存。

RTX 5070、16 GB 系统内存的电脑可优先尝试默认的 7B FP16 运算量化模型。系统内存不等于显存：RTX 5070 桌面版通常为 12 GB 显存，笔记本版本可能不同，请以实际规格为准。这个建议依据官方目录的显存估算，不是本项目在该显卡上的实测保证。其他程序、浏览器 GPU 限制、驱动和上下文缓存都会影响可用显存。资源不足或初始化失败时改用 1.5B；不支持 `shader-f16` 时程序自动切换到同大小的 FP32 兼容版本。没有可用 WebGPU 时会显示原因，不会把模板回答伪装成 AI。

浏览器必须处于安全上下文（HTTPS；本地开发可用 localhost）。仅有独立显卡并不保证浏览器能访问它。可在浏览器“系统”设置检查硬件加速，必要时在 Windows 图形设置中为浏览器选择高性能 GPU。模型首次启动也需要网络，WebGPU 本身不提供下载通道。

## 模型与资源预算

模型 ID 和显存数值来自安装的 WebLLM 0.2.85 官方 `prebuiltAppConfig`，界面元数据在 `src/services/localTutor.ts`。四个配置使用同一 4-bit 量化系列；FP16/FP32 是运算兼容配置，不是将模型变成完整的 16/32-bit 原始权重。

| 精确模型 ID | 官方 `vram_required_MB` | 使用建议 |
| --- | ---: | --- |
| `Qwen2.5-Coder-7B-Instruct-q4f16_1-MLC` | 5106.67 | 默认，优先尝试 |
| `Qwen2.5-Coder-1.5B-Instruct-q4f16_1-MLC` | 1629.75 | 较低 GPU 开销 |
| `Qwen2.5-Coder-7B-Instruct-q4f32_1-MLC` | 5900.09 | 不支持 FP16 时的兼容版 |
| `Qwen2.5-Coder-1.5B-Instruct-q4f32_1-MLC` | 1888.97 | 兼容且较轻量 |

这些是官方**显存需求估算**，不是下载字节数、实际峰值或最低系统内存。首次缓存可能达到 GB 量级；建议预留至少 10 GB 可用磁盘空间，这是使用建议而非已经核实的模型包大小。精确下载量应以所选仓库的文件清单和浏览器实际传输为准；本项目尚未能独立读取这些仓库的分片清单，不提供虚假的精确大小。

本地有效上下文为 **4096 tokens**，单次最多生成 **512 tokens**。不能使用上游原始模型宣称的 32K/128K 上下文来描述这里的浏览器配置。为留出回答和聊天模板空间，本地请求有保守的 3000 UTF-8 字节预算；优先保留当前问题，压缩最近对话、代码、错误和输出。超出问题预算会提示拆分，不会静默截掉当前问题。很长的源码应拆成片段，不能假定导师看到了完整项目。

## 下载来源、缓存与隐私

默认权重来自 `https://huggingface.co/mlc-ai/<model-id>/`，只允许上表模型；模型配置取自固定版本 WebLLM 的官方目录，不接受任意用户输入的模型 URL。WebAssembly 模型库来自：

`https://raw.githubusercontent.com/mlc-ai/binary-mlc-llm-libs/main/web-llm-models/v0_2_84/base/`

目录的兼容版本标记 `v0_2_84` 是 WebLLM 0.2.85 官方配置本身指定的值，并非安装版本错误。远端模型仓库和库 URL 使用上游当前分支，尚没有 CodeGrow 自己的完整权重/模型库哈希锁定清单；它们的信任边界是所选下载来源，不要把编译器的 SHA-256 校验描述成 AI 权重也已验证。

如果自己电脑无法访问 Hugging Face，可以**主动选择**“HF Mirror 社区镜像（第三方）”。这只将权重仓库基础域名替换成 `https://hf-mirror.com/`，模型库仍来自官方 GitHub。镜像不是 Qwen 或 MLC 官方服务，CodeGrow 不保证其可用性、传输速度或文件完整性，也不会悄悄切换下载来源；不要为其输入 Hugging Face 密钥或账号凭据。

下载需要向所选文件服务发送网络请求，服务方能看到常规请求信息，如 IP 和所请求模型。**本地 AI 的代码、问题和推理过程不发送到模型 API**；但这不意味着打开网站完全没有网络流量。切换到“自建 AI 代理”后，发送消息会向所配置代理传输教学上下文，属于另外一种隐私和费用模式。

WebLLM 会使用浏览器站点缓存保存已下载资源，后续可复用；浏览器可能因存储压力、隐私模式或清理站点数据而删除缓存，切换模型/来源也可能增加缓存占用。刷新页面会释放当前 GPU 模型，需要重新加载到显存，不保证全离线启动。“释放显存”不等于删除下载缓存。要删除下载资源，可在浏览器设置中清除本站缓存/站点数据；**清除全部站点数据也可能删除 CodeGrow 的本地学习记录，请先导出学习档案**。

## 权重许可与开源边界

CodeGrow 自己的代码使用 MIT；WebLLM 使用 Apache-2.0，运行时依赖 loglevel 使用 MIT。Qwen 官方模型发布文档明确：Qwen2.5-Coder **1.5B 和 7B 权重采用 Apache-2.0**，并说明每种尺寸都提供 Base 和 Instruct。本功能仅提供这两种尺寸，不提供使用不同 Qwen-Research 条款的 3B。

权重许可证据是[Qwen 官方固定版本发布文档](https://github.com/QwenLM/qwenlm.github.io/blob/7e70adff995f86c62e7ad1fe3c8645dc9f0a48ef/content/blog/qwen2.5-coder-family/index.md)，不是用代码仓库 LICENSE 代替权重许可。原文相关段落、Apache 完整条款、WebLLM 与 loglevel 许可以及来源/哈希保留在 [第三方许可清单](../THIRD_PARTY_NOTICES.md) 和 `resources/licenses/SOURCES.json`。

验证边界：本次云环境代理对 Hugging Face 的 HTTPS CONNECT 返回 403，无法独立读取 MLC 量化仓库自己的 LICENSE/NOTICE、模型卡和文件清单。这是当前环境的代理拒绝，不是远端要求登录的证据，也不表示用户电脑必然不能下载。项目没有下载或重新托管权重，不声称已逐文件审计量化发行包；将来若自行镜像、修改或分发权重/模型库，必须先取得原发行包、确认并保留适用许可和 NOTICE。

## 验证与排障

自动测试可以验证模型白名单、显卡能力检测、显式加载、取消、超时、流式回答和错误提示；模拟 WebLLM 的测试不等于完成真实 GPU 推理。CI/本云环境没有可用于验证 RTX 5070 的实体 GPU，也没有下载完整模型，所以真实权重加载、中文教学质量、速度和显卡兼容性仍需要用户电脑上的端到端验证。

建议首次手工检查：

1. 页面刚打开时，开发者工具网络面板没有模型权重分片下载；点击加载后才开始。
2. 等待模型就绪，问“用中文解释 C 语言 for 循环，给一个小例子”，确认回复逐步出现，随后运行例子验证。
3. 发送一段故意缺分号的代码和实际编译错误，检查导师是否解释了对应原因；不要仅凭语言流畅判断正确。
4. 尝试停止回答、取消加载、释放显存和从缓存重新加载，检查状态恢复；网络/显存失败应显示错误，不能假装已回答。
5. 下载失败时先检查自己的网络、文件源、浏览器缓存空间和驱动，再主动决定是否选择第三方镜像；浏览器开发者工具里的具体失败 URL 有助于定位。
